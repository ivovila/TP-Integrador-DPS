# Frontend · interfaz completa sobre puertos · Plan de implementación

**Goal:** Construir en `certiflow-frontend/` la interfaz de todas las capacidades actuales de CertiFlow, sin llamar a la API, sobre puertos propios y un adaptador en memoria que aplica las reglas de negocio.

**Architecture:** `ui` depende solo de `ports` y `domain`; `adapters/inmemory` implementa los puertos; `composition.ts` es el único archivo que conoce el adaptador. Las pantallas muestran las acciones que el puerto entrega con cada recurso y resuelven todo lo que depende del tipo de regla en un registro.

**Tech Stack:** Node 24, Vite 8, React 19, TypeScript 7 (`strict`), React Router 7, Vitest 5, Testing Library.

**Spec:** [docs/specs/2026-10-12-frontend.md](../specs/2026-10-12-frontend.md)

## Global Constraints

- No se modifica ningún archivo de `certiflow-domain`, `certiflow-application`, `certiflow-infrastructure` ni `certiflow-web`.
- Ningún archivo de `src/ui` importa de `src/adapters`. Ningún archivo de `src/adapters` importa de `src/ui`.
- Los métodos de los puertos llevan el nombre del caso de uso del dominio y devuelven `Promise`.
- Los errores de negocio son `DomainError` con el nombre de la excepción del dominio.
- Ninguna pantalla decide una acción mirando `closed` o `status`: usa `resource.actions`.
- Nombres largos y explícitos. Sin comentarios explicativos en el código. Interfaz en inglés.
- Commits sin `Co-Authored-By` ni atribución; un commit por tarea, mensaje en inglés y en imperativo.
- Cada tarea termina con `npm run typecheck && npm test && npm run build` en verde dentro de `certiflow-frontend/`.

## Review Focus

1. **Una pantalla no conoce el adaptador.** `grep -r "adapters" src/ui` no devuelve nada.
2. **El estado derivado no se guarda.** Resultado de un criterio, inspección cerrada, hallazgo abierto, acción vencida y estado del certificado se calculan al leer, con la fecha del reloj.
3. **Una operación rechazada no cambia nada.** Cerrar con criterios pendientes deja la inspección abierta y sin entradas nuevas en la bitácora.
4. **Los datos de ejemplo pasan por los comandos**, no se escriben directo en el almacén: así cumplen las reglas y tienen su historial.
