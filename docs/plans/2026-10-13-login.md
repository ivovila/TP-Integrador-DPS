# Login y logout · Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Autenticar cada request con Spring Security (Basic en cualquier path que devuelve un JWT; logout revocando el token actual) y aplicar los roles en la API.

**Architecture:** Usuarios y tokens revocados en `certiflow-infrastructure` (`infrastructure.security`, tablas en `V1__init.sql`). La seguridad vive en `certiflow-web` (`web.security`): resource server JWT de Spring + `httpBasic()`, un filtro que emite el token tras un Basic exitoso, un validador de revocación y `@PreAuthorize` en cada escritura. En el frontend, un puerto `AuthenticationPort` con su adaptador HTTP; `HalClient` obtiene las credenciales de una `CredentialSource` (la sesión del navegador, o un login por persona en scripts y suites e2e).

**Tech Stack:** Spring Boot 4.1.1 (`spring-boot-starter-security`, `spring-boot-starter-oauth2-resource-server`, `spring-security-test`), JPA + Flyway, H2 en tests; React 19 + Vitest en el frontend.

**Spec:** [docs/specs/2026-10-13-login.md](../specs/2026-10-13-login.md)

## Global Constraints

- `certiflow-domain` y `certiflow-application` no cambian.
- Tablas nuevas dentro de `V1__init.sql`; no se crea `V5`. Las bases locales se recrean.
- Headers de respuesta tras un Basic exitoso: `Authorization: Bearer <jwt>` y `Token-Expires: <ISO-8601>`.
- Claims del JWT: `sub` (id de persona), `name`, `role`, `jti` (UUID), `iat`, `exp`; HMAC-SHA256.
- Propiedades: `certiflow.security.jwt.secret` (mínimo 32 bytes, `${CERTIFLOW_JWT_SECRET:<valor de desarrollo>}`) y `certiflow.security.jwt.ttl` (por defecto `PT1H`).
- Roles: `ADMINISTRATOR`, `INSPECTION_COORDINATOR`, `INSPECTOR`, `ASSET_RESPONSIBLE`, `VERIFIER`, `CERTIFICATION_OFFICER`; autoridad `ROLE_<rol>`.
- Logout: `DELETE /api/v1/tokens/current` → 204; con Basic → 400.
- 401 y 403 en problem+json. Sin `WWW-Authenticate: Basic` cuando el request trae `X-Requested-With: XMLHttpRequest`.
- Usuarios de ejemplo (contraseña `certiflow`) solo con los perfiles `demo` y `demo-users`.
- Sin comentarios explicativos en código nuevo. Nombres largos y explícitos. Interfaz en inglés.
- Commits sin `Co-Authored-By` ni atribución; un commit por tarea, mensaje en inglés y en imperativo. Sin push.

## Review Focus

1. **Un Basic correcto sobre un request que falla** (404, 409, 403) igual devuelve el token: el login no depende del endpoint elegido. Test en Task 2.
2. **Un token revocado sigue siendo rechazado aunque no haya vencido**, y revocar no afecta a otro token de la misma persona. Test en Task 2.
3. **El navegador no abre su diálogo de login**: los 401 a requests con `X-Requested-With` no llevan `WWW-Authenticate: Basic`. Test en Task 2 (backend) y Task 5 (`HalClient` manda el header).
4. **El proceso completo sigue siendo posible con los seis usuarios**: los flujos e2e y la suite de contrato pasan contra el backend real. Task 5 y Task 7.
5. **Un 401 a mitad de uso (token vencido) devuelve al login** en lugar de dejar la pantalla con un error. Test en Task 6.

`SecurityConfiguration` (`@Configuration @EnableMethodSecurity @EnableConfigurationProperties(JwtProperties.class)`):

```java
@Bean
SecurityFilterChain api(HttpSecurity http, IssueTokenAfterBasicFilter issueToken,
                        ProblemAuthenticationEntryPoint entryPoint, ProblemAccessDeniedHandler accessDenied) throws Exception {
    return http
            .csrf(csrf -> csrf.disable())
            .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(requests -> requests.anyRequest().authenticated())
            .httpBasic(basic -> basic.authenticationEntryPoint(entryPoint))
            .oauth2ResourceServer(server -> server.jwt(jwt -> jwt.jwtAuthenticationConverter(SecurityConfiguration::authenticationOf))
                    .authenticationEntryPoint(entryPoint).accessDeniedHandler(accessDenied))
            .exceptionHandling(handling -> handling.authenticationEntryPoint(entryPoint).accessDeniedHandler(accessDenied))
            .addFilterAfter(issueToken, BasicAuthenticationFilter.class)
            .build();
}

@Bean
SecretKey jwtKey(JwtProperties properties) {
    return new SecretKeySpec(properties.secret().getBytes(StandardCharsets.UTF_8), "HmacSHA256");
}

@Bean
JwtEncoder jwtEncoder(SecretKey jwtKey) {
    return NimbusJwtEncoder.withSecretKey(jwtKey).build();
}

@Bean
JwtDecoder jwtDecoder(SecretKey jwtKey, NotRevokedValidator notRevoked) {
    NimbusJwtDecoder decoder = NimbusJwtDecoder.withSecretKey(jwtKey).macAlgorithm(MacAlgorithm.HS256).build();
    decoder.setJwtValidator(new DelegatingOAuth2TokenValidator<>(JwtValidators.createDefault(), notRevoked));
    return decoder;
}

@Bean
PasswordEncoder passwordEncoder() {
    return PasswordEncoderFactories.createDelegatingPasswordEncoder();
}

private static AbstractAuthenticationToken authenticationOf(Jwt jwt) {
    return new JwtAuthenticationToken(jwt, List.of(new SimpleGrantedAuthority("ROLE_" + jwt.getClaimAsString("role"))), jwt.getSubject());
}
```

`JwtProperties` valida en el constructor compacto que `secret` tenga al menos 32 bytes (si no, `IllegalStateException` al arrancar).

`UserAccountDetailsService implements UserDetailsService`: busca por id; devuelve `User.withUsername(personId).password(hash).roles(role).build()`; si no existe, `UsernameNotFoundException`. El nombre de la persona se lee de nuevo del repositorio al emitir el token.

`TokenIssuer`: arma `JwtClaimsSet` (`sub`, `name`, `role`, `jti` = `UUID.randomUUID()`, `iat` = `clock.instant()`, `exp` = `iat + ttl`) y lo codifica con `JwsHeader.with(MacAlgorithm.HS256)`.

`IssueTokenAfterBasicFilter extends OncePerRequestFilter`: si el `Authentication` del contexto es un `UsernamePasswordAuthenticationToken` autenticado (vino de Basic), carga la cuenta, emite el token y pone `Authorization` y `Token-Expires` en la respuesta **antes** de `chain.doFilter` (los headers deben estar antes de que el controlador escriba el cuerpo).

`NotRevokedValidator implements OAuth2TokenValidator<Jwt>`: falla con `OAuth2Error("invalid_token")` si `revokedTokens.existsById(jwt.getId())`.

`ProblemAuthenticationEntryPoint`: responde 401 `application/problem+json` (`title` = `Unauthorized`). Agrega `WWW-Authenticate: Basic realm="certiflow"` salvo que el request traiga `X-Requested-With: XMLHttpRequest`. `ProblemAccessDeniedHandler`: 403 problem+json (`title` = `Forbidden`). Ambos escriben con el `JsonMapper` de Spring.

`TokenController` (`@RestController @RequestMapping("/api/v1/tokens")`):

```java
@DeleteMapping("/current")
@Transactional
public ResponseEntity<Void> revokeCurrent(Authentication authentication) {
    if (!(authentication instanceof JwtAuthenticationToken token)) {
        throw new InvalidRequestException("Only a bearer token can be revoked; log in first");
    }
    revokedTokens.deleteByExpiresAtBefore(clock.instant());
    revokedTokens.save(new RevokedTokenEntity(token.getToken().getId(), token.getToken().getExpiresAt()));
    return ResponseEntity.noContent().build();
}
```

`ActingPersonResolver`: toma el `Authentication` de `SecurityContextHolder`. Si es `JwtAuthenticationToken`: `new Person(new PersonId(jwt.getSubject()), jwt.getClaimAsString("name"))`. Si viene de Basic: busca la cuenta por `authentication.getName()` y usa su nombre. Se quitan las constantes y los chequeos de headers; `WebConfiguration` pasa el repositorio de cuentas al resolver.

**Interfaces:**

```ts
export type StaffRole = 'ADMINISTRATOR' | 'INSPECTION_COORDINATOR' | 'INSPECTOR' | 'ASSET_RESPONSIBLE' | 'VERIFIER' | 'CERTIFICATION_OFFICER';

export interface SignedIn {
  person: Person;
  role: StaffRole;
  expiresAt: string;
}

export interface AuthenticationPort {
  current(): SignedIn | undefined;
  logIn(personId: string, password: string): Promise<SignedIn>;
  logOut(): Promise<void>;
  onSignedOut(listener: () => void): () => void;
}
```

```ts
export interface CredentialSource {
  headersFor(actingPerson: Person | undefined): Promise<Record<string, string>>;
  received(response: Response, actingPerson: Person | undefined): void;
  rejected(): void;
}
```

  - `BrowserSession implements CredentialSource, AuthenticationPort`: un token en `sessionStorage` (`certiflow.token`); `headersFor` devuelve `Authorization: Bearer` (si hay) y siempre `X-Requested-With: XMLHttpRequest`; `logIn` hace `GET /api/v1` con Basic y guarda el `Authorization` de la respuesta; `logOut` hace `DELETE /api/v1/tokens/current` y borra el token aunque falle; `rejected()` borra el token y avisa a los `onSignedOut`. `SignedIn` sale del payload del JWT (base64url de la segunda parte).
  - `PersonLogins implements CredentialSource` (`constructor(password: string, reader: Person)`): por persona, Basic la primera vez y después el Bearer que devolvió; sin persona (lecturas) usa `reader`.
  - `HalClient(baseUrl, credentials: CredentialSource, fetchFunction?)`: `read` llama `headersFor(undefined)`, `write` `headersFor(actingPerson)`; después de cada respuesta `received(...)`; con 401 llama `rejected()` antes de lanzar el error.
  - `createHttpCertiflow(baseUrl, credentials, fetchFunction?)`.
